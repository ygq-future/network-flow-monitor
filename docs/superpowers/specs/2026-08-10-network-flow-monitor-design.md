# Network Flow Monitor 设计规格

- 日期：2026-08-10
- 状态：待书面规格评审
- 目标版本：首个可用版本

## 1. 问题与目标

在 Windows 11 上提供一个体积和运行开销都尽量小的实时网络监控工具。工具常驻通知区，可显示桌面悬浮窗；用户悬停时查看最近时间窗口内网络速率最高的应用。

成功体验包括：启动快、平时不打扰、排行反应及时、多进程应用不会重复占榜、悬浮窗在多显示器和不同 DPI 下保持可见、绿色模式与服务模式能从同一设置界面切换。

## 2. 已确认范围

- Windows 11 24H2 x64 作为首发基线。
- C++20、CMake、Win32、Direct2D、DirectWrite。
- 通知区图标、悬浮窗、贴边隐藏和动态定位排行面板。
- TCP/UDP、IPv4/IPv6 的 ETW 元数据采集。
- 实时上传、下载、合计速率与应用 Top N。
- 同一应用多进程聚合。
- 绿色提权采集器与可选 Windows 服务双模式。
- 带 UI 的服务安装、启动、停止、重启、卸载和启动类型配置。
- 以 clang-format、clang-tidy、MSVC 严格警告、双重静态分析、测试和 Release 构建组成强制提交门。

## 3. 明确非目标

- 不嵌入或修改 Windows 11 任务栏。
- 不开发驱动，不检查报文载荷。
- 不限速、不阻断连接、不结束应用。
- 不保存长期流量历史，不做云同步、插件、账号或自动更新。
- 首个版本不支持 ARM64；架构不得故意阻断以后增加 ARM64。

## 4. 用户体验

### 4.1 首次运行

默认以普通权限 UI 启动。若没有服务，UI 解释绿色采集器会触发 UAC，并在用户同意后启动同一 EXE 的 `--collector` 模式。拒绝 UAC 时 UI 仍可打开设置和帮助，但不能伪装为正在实时采集。

### 4.2 托盘与悬浮窗

- 左键托盘图标切换悬浮窗。
- 右键打开常用菜单和设置。
- 托盘或悬浮窗悬停达到配置延迟后打开排行面板。
- 悬浮窗显示总上传和下载，支持拖动、吸附、隐藏和恢复。
- Windows 控制托盘图标是否进入溢出区；应用只提示用户固定，不尝试绕过系统策略。

### 4.3 排行面板

- 默认 Top 5，范围 1–20。
- 每行显示应用图标、名称、下载、上传和合计速率。
- 速率按最近配置窗口计算，默认 2000ms。
- 可见数据默认每 500ms 更新一次。
- 面板从当前锚点向可用空间最大的合适方向展开，并被钳制在当前显示器工作区。

### 4.4 设置与服务

“采集与服务”页面必须显示当前模式、采集连接、服务安装和运行状态，并提供绿色/服务模式切换、安装、启动、停止、重启、卸载及启动类型设置。系统修改通过明确的 UAC 操作执行；完成后重新查询 SCM 验证。

## 5. 配置语义

ETW 事件是连续事件流。公开给用户的两个数据时间参数是：

- `ranking.window_ms`：速率使用的历史窗口。
- `display.refresh_interval_ms`：累计计数快照和可见数据更新周期。

没有独立的“UI 刷新率”。UI 仅在收到快照或视觉状态变化时重绘。Top N、窗口、数据显示刷新间隔、悬停/消失延迟、贴边和自动隐藏参数都必须来自统一、带版本且有校验的配置模型。完整表见 `docs/configuration.md`。

## 6. 组件与数据流

### 6.1 Collector

高权限 Collector 负责 ETW、进程生命周期、应用身份解析和每应用累计字节。它不计算某个用户的 Top N，也不保存某个用户的窗口配置。

### 6.2 IPC

Collector 通过带显式 ACL 和版本帧协议的命名管道向 UI 发布累计计数快照。客户端握手携带期望的数据显示刷新间隔；服务校验范围后按订阅推送。

### 6.3 UI

UI 保存短期累计快照历史，用真实单调时间差计算窗口速率，完成应用排序和 Top N。新快照到达后仅重绘数据相关区域。

### 6.4 运行模式

同一二进制按入口参数成为 UI、临时采集器、服务或提权服务管理代理。安装服务时把二进制复制到稳定 Program Files 路径，不能注册易移动的绿色版文件。

## 7. 权限与安全

- UI 始终普通权限。
- 服务或临时采集器仅获得完成采集和服务管理所需权限。
- 命名管道使用显式 DACL、协议版本、长度校验和命令白名单。
- 不采集报文载荷；诊断日志不写敏感命令行参数和不必要的远端地址。
- 服务管理代理只接受固定动作，不提供任意命令执行能力。

## 8. 故障行为

- 采集器断线时显示断线状态，清除“实时”语义并自动有限退避重连。
- ETW 事件丢失或缓冲压力进入健康状态，超过阈值时提示排行可能不完整。
- 无法读取进程路径时保留字节并显示系统/未知宿主，不虚构应用归属。
- UI 与服务协议不兼容时拒绝连接并提示升级不一致。
- 配置损坏时保留损坏副本、使用安全默认值并提供恢复入口。

## 9. 代码质量与提交门

C++ 没有一个工具能独自覆盖 ESLint 的全部角色。项目组合使用：

- 根目录 `.clang-format` 统一 C/C++ 格式。
- 根目录 `.clang-tidy` 执行 bug-prone、CERT、Clang Static Analyzer、并发、Core Guidelines、现代化、性能、可移植性和可读性检查。
- MSVC 对第一方代码启用 `/W4 /WX /permissive- /sdl`，并单独执行 `/analyze`。
- CTest 验证行为，Release x64 构建验证交付配置。

实现阶段提供 `tools/quality.ps1`。每个功能完成后运行格式化和快速质量门；每次 Git commit 前运行全量质量门。任何步骤失败都不能提交。检查通过不自动授权代理创建提交，仍需遵守用户授权。

## 10. 测试策略

- 单元测试覆盖窗口计算、刷新间隔边界、Top N、累计计数、PID 复用和应用合并。
- 集成测试用受控 TCP/UDP 发生器验证 IPv4/IPv6、短连接和并发应用。
- IPC 测试覆盖 ACL、协议版本、恶意长度、断线重连和多个 UI 客户端。
- UI 手工与自动检查覆盖混合 DPI、多显示器、任务栏自动隐藏和工作区变化。
- 服务测试覆盖安装、启停、重启、启动类型、模式切换和卸载。
- Release 原型完成后记录体积、CPU、工作集、事件丢失和端到端数据显示延迟，再将合理数值写入性能验收标准。

## 11. 验收条件

- 用户可完全通过 UI 配置 Top N、排行窗口、数据显示刷新间隔和悬停行为。
- 用户可完全通过 UI 查看并管理服务状态；命令行不是唯一入口。
- 同一应用多个进程只出现一个排行项。
- 悬浮窗和排行面板不会越出当前显示器工作区，DPI 或工作区变化后能恢复有效位置。
- 绿色模式除 UAC 外不要求安装；服务模式安装后开机采集无需每次 UAC。
- 采集器或 IPC 失败时 UI 不继续把陈旧值标记为实时数据。
- 不包含任务栏注入、内核驱动或报文载荷采集代码。
- 根级格式和 lint 配置可由本机 Visual Studio LLVM 工具解析。
- 每个准备提交的功能都在 `docs/planning/progress.md` 留有全量质量门通过记录。

## 12. 后续步骤

书面规格经用户确认后，创建逐任务实现计划；先建立 CMake 预设和统一质量脚本，再依次实现纯逻辑排行核心、ETW 采集原型、IPC、双模式宿主、托盘/悬浮窗、设置与服务管理，最后进行集成和性能验证。
